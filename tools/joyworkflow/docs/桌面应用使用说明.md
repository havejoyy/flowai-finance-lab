# JoyWorkflow 0.5.2 桌面版

## Windows 0.5.2 便携版

下载Windows x64 ZIP，先完整解压到可读写文件夹，再双击 `JoyWorkflow.exe`。无需安装Python、数据库或Node；不需要管理员权限。必须保留同级 `_internal` 文件夹，不要在压缩包内直接运行。启动器就绪后自动在默认浏览器打开研究页面，也可点击“打开研究页面”。

数据保存在 `%LOCALAPPDATA%\JoyWorkflow`。启动器可打开数据目录、查看 `desktop.log`。旧数据可在退出原服务后通过 `JoyWorkflow.exe --data-dir "原数据文件夹"` 指定。更新应用不覆盖外置数据。关闭浏览器页不会停止服务，退出启动器会停止本地服务；运行中退出会提示，中断任务在重启时保留并恢复为中断状态。

目标Windows10/11 x64，自动化环境为GitHub Windows x64 runner，用户机器人工首开尚未验证。本包未进行Authenticode签名；系统如拦截，不要求关闭安全保护。Windows ARM尚未验收。

## Mac 0.5.2 使用

本次构建适用于 Apple Silicon（M1/M2/M3/M4 等）Mac，macOS 13 及以上。内置 CPython、SQLite 和证书，无需安装 Python、Node、数据库或 Skill，无需填写行情 API Key。实际验收在当前 arm64 Mac 完成，未验证其他Mac首开或Intel Mac；Windows请使用独立便携包。

1. 解压 `dist/desktop/JoyWorkflow-macOS-AppleSilicon-0.5.2.zip`，双击 `JoyWorkflow.app`；也可将应用拖到“应用程序”。
2. 选择策略模板，或在“我的策略”添加五层指标、调整阈值并保存版本。
3. 点击“获取数据并运行筛选”。首次需要联网，后续先检查本地 SQLite，按时效和日期复用、补取或增量更新。
4. 在“历史筛选”查看报告。入选、条件不符、未纳入核验、数据缺失分别展示。相同版本已有记录时可直接回看，或选择重新运行。

本包仅有本地 ad-hoc 签名，尚未完成 Apple Developer ID 签名和公证，不能保证下载到另一台 Mac 后无系统拦截。正式对外分发前需完成签名、公证与干净机器验收。本说明不要求关闭系统安全校验。

## Mac数据在哪里

默认：`~/Library/Application Support/JoyWorkflow/`，数据库为 `workflow.sqlite3`。首次启动创建目录和表，已有观察记录保留；更新应用不会覆盖外置数据。菜单“打开数据文件夹”可查看，备份时先退出应用再复制整个文件夹。

旧版迁移：退出占用旧数据目录的旧版服务，通过菜单“切换本地数据文件夹…”选择包含 `workflow.sqlite3` 的文件夹。应用记住选择，不删除原目录。一个数据目录同时只允许一个服务实例；桌面服务自动选择空闲回环端口。

发布 ZIP 不包含数据库、用户策略、日志、凭据或内部验收记录。已有 SQLite 可通过原生菜单选择数据文件夹复用。

## 自动恢复与明确缺失

两个平台的 0.5.2 桌面版均提供独立更新入口：打开“本地数据”，点击右上角“获取最新数据”。它会重新联网获取收盘快照和行业分类，显示进度，完成后刷新日期和本地数据表。有缺口时显示“部分更新完成”并列出具体原因，可再次点击重新获取；失败时保留原有数据。个股历史日 K 等策略资料在筛选时继续按需补齐，已有历史报告保留原日期。该入口使用收盘数据校验，盘中或收盘整理时段会提示稍后再试。

- 可恢复的断线、超时、限流或服务端暂时异常：逻辑层最多执行两次（一次重试），传输层另有有限备用与尝试。页面显示实际重试次数，最终失败保留原因。
- 获取快照后自动复查无效报价，只有同一行情日期、非零且字段完整的报价才替换。来源目录未覆盖的证券单列，不补成零或示例。
- 日期、字段、历史口径、指纹或行业覆盖校验不通过：不能作为有效缓存发布，缺失维持“待核验”。证书失败和拒绝访问不盲目重试。
- 报告显示行情日期、资料日期、复用/获取数量、缺失原因和未核验范围。点击“重试缺失数据”生成关联的新任务，原报告保留。
- 收盘型工具在交易日历上核对最近交易日。休息日显示最近交易日日期；不会把旧日结果标成今日行情。来源已换日期的旧任务重试需要重新运行，避免拼接两天数据。
- 无网络时可回看本地历史，不承诺生成新的完整结果。关闭应用停止取数；不后台每日更新。
- 启动失败可重试或查看 `desktop.log`。磁盘或权限错误需先恢复目录可写。运行中退出会提示，下次启动恢复时将未完成任务标为中断。

## 技术与构建

Windows使用Tk原生启动器、默认浏览器和冻结的Python后端；只监听本机，不开放局域网。Windows开发机安装 `desktop/windows-build-requirements.txt` 并运行 `build_windows.py`；用户无需开发依赖。

Mac使用原生 AppKit/WKWebView 窗口，内置 PyInstaller onedir 后端，只监听 `127.0.0.1`。筛选由规则代码计算，未调用 AI 模型。

开发机需 Apple 命令行工具、Python 3.12（本次 3.12.14），安装 `desktop/build-requirements.lock` 后执行 `python build_desktop.py`。用户端不需要这些依赖。构建使用资产白名单；不打包私有数据库。Skill 资源按 manifest 校验。

TLS 保持证书与主机名验证。申万服务器缺失的中间证书从 DigiCert 的验证 HTTPS 镜像获取，构建时必须链到 certifi 已有根，未信任叶证书或添加新根；运行时撤信文件原样保留。细节见 `desktop/certificates/README.md`。

公开验收摘要见本工具 README。本次 10 只历史核验上限用于功能验证，不代表对 135 只候选全部核验，更不代表策略收益验证。
